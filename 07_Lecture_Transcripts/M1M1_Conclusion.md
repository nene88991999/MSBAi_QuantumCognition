# M1M1_Conclusion

That brings us to the end of Module 1. Let's take a moment to look back.

The big idea was that the way we ask a question belongs in the analysis. A survey or a review might reveal a view the person already held.

Or it might help form the answer that the organization later treats as data. Our fraud-review and shopping examples showed why that difference matters: each possibility leads you to ask different questions about the process.

So how do you investigate it? The first step is to state a benchmark, the pattern a model says you should see.

Then ask what changed in the process. Did asking for an assessment change a later action?

Did reversing two questions change how the answers paired up? Did combining two ideas change how people judged them?

Each of these comparisons tests a particular assumption. So when a result surprises you, you can say exactly which assumption it challenges.

The next step is to compare explanations. Learning, memory, and uneven wording can produce some of the same patterns as a quantum model.

So the quantum model earns our attention only when its predictions succeed, especially predictions made before seeing a new task, and predictions about when an order effect should disappear. Tests like these give the model a real chance to fail, and that's what makes passing them meaningful.

As we move on, keep one question in mind: what result would make you reconsider your favorite explanation? In Module 2, we'll focus on question order, and use it to build an audit, which is a planned comparison of different ways of asking.

We'll also learn how to tell whether a difference is precise enough to guide a real decision. See you there.
